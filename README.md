# LifeBeacon Station

支持 RTL-SDR 接收及 HackRF 收发的 LoRa/LifeBeacon 工作站。完整离线依赖包见 [v1.1.0 Releases](https://github.com/cyx728/LifeBeacon_Station/releases/tag/v1.1.0)，按操作系统和 CPU 架构下载；同名 `.sha256` 文件用于校验下载完整性。

## 运行方式（LifeBeacon Station）

### Windows：发布包

1. 解压 `LifeBeacon-Station-v1.1.0-windows-x64.zip` 到较短、无特殊字符的目录，例如 `C:\LifeBeacon`。Windows 的 Qt DLL 加载可能受过长路径限制影响；启动器不会映射盘符，失败时会在包目录写入 `startup-error.log`。
2. 双击 `Start-Station.cmd`，或在 PowerShell 中运行：

   ```powershell
   # 进入解压后包含 Start-Station.cmd 的实际目录
   Set-Location C:\LifeBeacon\LifeBeacon-Station-v1.1.0-win-64
   .\Start-Station.cmd
   ```

   首次运行会从 `packages` 离线安装 `runtime`，不需要联网；请等待安装完成。之后启动器直接运行 `app\station.py`。
3. 选择设备。RTL-SDR 用接收下拉框；Black SDR HackRF Pro 选择以 `hackrf=` 开头的设备。HackRF 选中后右侧出现发送面板。
4. 点击“开始接收”。停止其他 SDR#、`rtl_tcp` 或 GNU Radio 程序，避免它们占用同一个 USB 设备。

### Windows：源代码运行

需要已安装本项目依赖的 Python/GNU Radio 环境。进入本目录后运行：

```powershell
Set-Location 'C:\Users\chen\OneDrive - Beijing 101 Middle High School\Projects\26-27 #1 Conrad Challenge\Program\LifeBeacon_Station'
.\Start-Station.cmd
```

只做 GUI 启动检查可运行 `.\Start-Station.cmd --gui-smoke-test`。数字 IQ 回环和协议检查需要先配置同一个运行时的 DLL 搜索路径：

```powershell
$stationRuntime = 'D:\LifeBeacon-build\station-runtime-verified'
$env:PATH = "$stationRuntime;$stationRuntime\Library\bin;$stationRuntime\Scripts;$env:PATH"
$env:CONDA_PREFIX = $stationRuntime
& "$stationRuntime\python.exe" .\verify_station.py
# 可选：只采集 HackRF，不发射
& "$stationRuntime\python.exe" .\probe_hackrf.py
```

以上 `D:` 路径是本机开发环境。其他电脑优先使用离线发布包；若使用自建依赖环境，需修改启动脚本中的运行时路径。

### macOS：发布包

根据芯片选择 `osx-64`（Intel）或 `osx-arm64`（Apple Silicon），解压后在终端运行：

```bash
cd /path/to/LifeBeacon-Station-v1.1.0-osx-64
chmod +x Start-macOS.command micromamba
./Start-macOS.command
```

首次运行会使用包内 `packages` 离线创建 `runtime`；macOS 可能需要在“系统设置 → 隐私与安全性”允许未签名程序运行。RTL-SDR/HackRF 的 USB 驱动和权限仍需按 macOS 环境单独安装。

## 实时日志显示设置

### 往期日志与范围统计

新日志第一条为 `record_type: receiver_config` 配置记录，包含设备参数/名称、中心频率、扫描带宽、采样率、LoRa 带宽、手动增益请求值与可读回的实际值、ppm、25 kHz 信道间隔、SF7–12、同步字、显式头、CRC/软解码/LDRO 设置、强度单位与合并窗口。时间含时区，使用 `config_id` 关联后续报文的 `receiver_config_id`。开始接收时立即记录，即使尚未收到报文；再次开始接收或运行中改变增益会追加配置记录。`configured_only` 表示只记录了界面配置，未声明硬件已启动；实际增益不可读回时为 null，不冒充测量值。

解码配置中的“严格校验同步字（推荐）”默认开启，使用界面同步字 `0x12`。关闭后向 `frame_sync` 传入 `[0, 0]`，启用 gr-lora_sdr 的同步字通配恢复，允许捕获同步字未知或与配置不符的 LoRa 帧；后续仍必须通过 PHY CRC 和 LB CRC，因此不会因为弱同步匹配直接写入有效报文，但会增加误检测和 CPU 负担。接收端配置头记录 strict/wildcard 模式。软判决、FFT 最大对数近似、显式头、SF7–12 并行和 LDRO 自动保持开启；相邻 25 kHz 分支继续使用原有隔离滤波，避免放宽滤波后两个相邻信号互相干扰。

JSONL 会话导出在报文前保留配置记录；CSV 在列名之后先写 `receiver_config` 行（`receiver_config_json` 保存完整配置），再写 `packet` 行。历史读取识别并跳过配置行，不将其计入包数、日志行号范围或损坏行；“接收端配置”按钮可查看日志头及变更记录。统计 CSV 同时保留源文件配置。旧日志没有配置头时仍可读取，既有历史文件不改写。`verify_receiver_config.py` 覆盖配置头、增益读回、配置变更、报文关联以及 JSONL/CSV 往返读取和统计。

“日志 → 读取往期日志”可同时选择多份 JSONL 或本程序导出的 CSV，在独立窗口读取全部报文，不受实时表格最近 500 行的限制，也不会覆盖实时会话、重新记录历史报文或改写源文件。双击报文仍可查看逐字段原始值和解码。导入逐行从原始十六进制重新解析，丢弃 PHY 未通过/未确认的行，损坏行单独计数；LB 失败保留原始报文和原因，可查看但不参与设备统计。旧格式缺少 PHY 标志时使用其原有 PHY CRC OK 状态；不会由原始 payload 推断 PHY 是否通过。

历史窗口的“范围统计”页，以及“日志 → 当前会话范围统计”，可选择读取后的日志行号（1 开始，含两端）或报文 sequence（0～255，含两端）。sequence 起点大于终点时按 255→0 跨界，例如 250～5；序号循环后的同序号报文都会计入，不能用它自动区分发送轮次。多文件按选取顺序拼接，不做跨文件去重；同时选入原日志及其 CSV 副本会重复计数。当前会话统计使用打开时的快照，接收继续运行但不自动改变本次统计样本；重新打开可获取最新快照。

统计总设备数、有效包数及排除行数，并按设备 ID 汇总包数、接收强度 MAX/MIN/AVG、强度有效样本数、心率/血氧有效数和有效率、AVG/MIN/MAX、按接收顺序列出的有效值。心率/血氧须协议标志置位且数值非 FF；没有有效样本时显示“—”，不以 0 填充。强度可选每包平均值或峰值，单位 dBFS（并非 RSSI 占位字节或校准 dBm），AVG 为各包 dBFS 的算术平均，缺失/非有限读数不参与计算。增益不同的历史样本读数会受增益影响，统计不做校准补偿。

“导出统计 CSV”保存设备汇总、有效值列表及范围/强度字段/源文件/总设备数与包数，便于复核；数值字段不随界面语言改变。`verify_log_analysis.py` 验证 JSONL/CSV 重新解码、损坏行、有效值、序号跨界、统计导出以及历史读取与实时记录隔离。

LB v1 周期报文逐条从各自的 `raw_payload_hex` 独立解码，不依赖前一条报文，也不信任传入记录中缓存的协议字段。协议长度为 `21 + name_length` 字节，设备 ID 和末尾 CRC 均为小端；应用 CRC 使用 CRC16-CCITT、初值 `0xFFFF`，覆盖末尾 CRC 之前的全部字节。PHY CRC 通过后仍需独立通过 LB 长度、版本/类型及 CRC 校验。

LB v1 的报文类型支持 0=广泛呼叫（CQ）、1=信标（beacon）、2=应答（response），三类沿用当前 LB v1 字段布局与 CRC 规则。主界面类型列及双击详情显示“数值（当前语言标注）”，中英文切换会刷新已有行；其他类型仍拒绝解析。JSONL 和 CSV 保留数值 `message_type`，并新增与界面语言无关的 `message_type_label`（CQ / beacon / response），既有历史文件不改写。

距离可视化圆点半径为 8，引线保持竖直向上。标签按实际设备 ID、强度文本和字体宽度计算边界；字体/DPI 样式变化会重新排布，避免 ID 被裁切。强信号标签避开天线图标，密集标签增加高度并在区域内滚动；原本停在滚动底部时，内容增高会继续跟随数轴，手动向上滚动时保留浏览位置。`verify_distance_labels.py` 覆盖密集同强度、0/−60 轴端、超出轴范围、长名称、3 种字号、两种坐标模式与滚动行为。

表格已提供所有协议字段的独立列：除原有设备、姓名、生理与状态字段外，新增 magic、版本、报文类型、姓名字节数、心率原始字节、血氧原始字节、LB CRC16。心率/血氧有效标志未置位或字节为 `FF` 时，测量值为“—”，原始值列仍显示 `0xFF`，不会误显示为 255 bpm 或 255%。RSSI 占位字节 `80` 保持为原始数值 128，不解释为接收端强度；电量 0 保持原值。双击任意报文可查看类似发射端 `[tx]` 的 `[rx]` 逐字段清单（17 个字段的字节偏移、原始十六进制与数值）。

新 JSONL 每行包含完整原始字节、解码 `fields` 和 `payload_fields`（精确字段名、含首尾的字节偏移、原始字节及解码值）；CSV 提供独立字段列及 `payload_fields_json`。LB 解码失败记录保留原始字节及失败原因，协议列为空，不会标为解码成功。既有历史文件不自动改写。可运行 `python verify_protocol.py --audit-logs`，以发射端提供的 `DEMO2_PCB` 报文验证字段、CRC、界面及导出，并只读检查历史日志能否独立解码及已有字段是否一致。

“设备颜色”使用设备 ID 的固定 SHA-256 映射至精选的 12 色马卡龙色板（浅粉、蜜桃、浅橙、柠檬、嫩绿、薄荷、浅青、天蓝、长春花、薰衣草、浅紫、樱粉），避免暗色、灰褐等浑浊色。表格背景与可视化设备标记使用相同映射；超时设备仍淡化。同一 ID 在重启、切换语言和不同接收顺序下保持同色。无有效设备 ID 的行使用白色，不同设备可能映射到同色。白灰交替、全白模式保持不变。

跨信道重复解码在界面和磁盘写入之前合并：在首个候选到达后的 750 ms 内，对原始 payload 字节完全相同、来自不同解码信道的候选，只输出平均信号强度（`signal_avg_dbfs`）最大的一条，信道中心频率及其它字段取自这一条。其他候选不会进入表格、可视化、自动日志或导出。显示增加最多约 800 ms 等待。后续相同内容的再次发送、同信道多次接收不会因内容相同而全局去重。未知/非有限强度低于有效测量值；相同强度保留先到者。合并依赖回调到达时间窗，严重处理积压导致候选间隔超过窗口时可能保留重复项。`verify_packet_merger.py` 验证合并、最强信道选择、日志行数以及重复发送保留。

顶部菜单顺序为“设备 / 日志 / 可视化 / 帮助 / 语言”。在“日志 → 编辑实时日志显示”中可逐列勾选显示、设置加粗，选中内容项后用上移/下移调整顺序；行配色可选择设备颜色、白灰交替、全白。PHY CRC 失败或未验证的报文在解码入口直接丢弃，不合并、不显示、不写日志，也不会出现在导出中。“显示 LB 解码失败报文”仅控制 PHY CRC 已通过但 LB 解析/应用 CRC 失败的报文是否显示；这些报文仍正常记录，方便协议分析。点确定后立即刷新最近 500 条符合条件的记录，设置保存到本机用户配置，下次打开沿用。此规则应用于今后的接收，不改写已有历史日志文件。

新增“接收中心频率 (Hz)”列，使用报文解码通道的 `channel_frequency_hz`。它是接收信道中心频率，不能当作精确的射频载波频偏测量；没有频率元数据的旧记录显示“—”。设置窗口跟随中英文语言，原始报文、机器可读日志字段不翻译。

## 带内并行扫描（当前 GUI）

接收配置的主参数为中心频率和扫描带宽，实际接收范围为中心 ± 扫描带宽/2。默认中心 433.775 MHz、扫描带宽 1000000 Hz；RTL 采样率 2400000 S/s。扫描带宽必须至少等于 LoRa 带宽，且不大于 RTL 采样率的 80%。

接收链在带内以固定 25000 Hz 间隔建立并行频移/滤波信道，信道中心对齐绝对频率的 25 kHz 网格，每个信道并行尝试 SF7–SF12。默认范围中包含 433.375 MHz 独立信道。频移滤波后先抽取再有理重采样，减少高采样率下后续处理量。LoRa 单信号带宽和同步字仍是解码约束：默认 BW125 kHz、sync 0x12、显式头。此版没有实现任意带宽/同步字/隐式头的盲解码，也不能保证解出所有任意频偏或互相碰撞的信号。边缘信号必须完整落在接收范围内。默认范围对应 35 个频率、210 路 SF 解码，CPU 和内存需求较高，实际实时性能需现场验证。

日志增加解码信道中心 `channel_frequency_hz`、扩频因子和 LoRa 带宽（信道中心不是精确的载波频偏测量）。频谱和瀑布图显示整个 RTL 采样频段。离线自检已覆盖两个同时载波（433.7125、433.8375 MHz）的有效 LB 报文，真实宽带接收仍需 RTL 硬件验证。

“可视化”现在位于“设备”“日志”等同一顶部菜单栏。距离窗口横轴改为 0、−10、…、−60 dBFS，设备按最新平均强度更新轴上位置，超出显示范围贴边并保留真实读数；不再显示百分比或米。超过 15 秒未更新仍会变淡。

可视化底部的 `Timeout: [15] (s)` 可即时调整超时秒数。坐标选项支持线性 dBFS，以及基于自由空间对数路径损耗（n=2）的相对距离映射：`ΔP = −20 log10(d/d₀)`，位置为 `(10^(−P/20)−1)/999`（P 截断在 −60～0 dBFS），刻度与设备使用相同映射。对数传播模式下靠近 0 dBFS 的刻度会密集，因此自动省略重叠的刻度文字。它假设发射功率、接收增益等条件一致，仍然不是经标定的米制测距。旧底部提示已移除。

软件部署位置：`D:\ProgramData\radioconda`。已验证 GNU Radio 3.10.12.0、gr-osmosdr、RTL-SDR 和 EPFL gr-lora_sdr 模块可加载，沿用已有安装。

## 启动

桌面 `LifeBeacon LoRa Receiver` 快捷方式打开专用接收 GUI。也可在本目录运行 `Start-LoRaReceiver.ps1`。

桌面 `LifeBeacon LoRa GRC` 快捷方式打开可编辑的 `RTL_SDR_LoRa_RX.grc`。也可运行 `Open-GRC.ps1`。GRC 流图用于查看、修改接收链，输出十六进制和 PHY CRC；专用 GUI 额外解析 LB 应用协议并保存日志。只运行一个接收器，避免抢占设备。

接上 RTL-SDR 后，在下拉框中选择设备，点击“开始接收 / Start reception”。运行前关闭占用同一个设备的 SDR#、rtl_tcp 或其他接收程序。除增益外的参数需停止接收后修改。

## 默认参数及数据链

- 433775000 Hz；扫描带宽 1000000 Hz；RTL 采样率 2400000 S/s；手动增益 28 dB；频率校正 0 ppm。
- LoRa BW 125000 Hz、SF7–12 并行扫描、同步字 0x12、显式头；编码率及 PHY CRC 存在标志从头部读取；soft decoding；LDRO 自动。
- RTL-SDR → 各信道频移/抗混叠滤波抽取 → 有理重采样至 4×LoRa BW → frame sync → FFT demod → Gray mapping → deinterleave → Hamming decode → header decode → dewhitening → PHY CRC verification。

GUI 为左右分栏：左上配置、左中频谱、左下瀑布图，右侧为完整解码表格。拖动中间分隔线可调整两侧宽度。图表横轴为相对调谐中心的频率偏移。

表格依次显示时间、原始十六进制报文、设备 ID、姓名、紧急等级、心率、SpO2、电量、序号、生理标志、生理保留字段、定位标志、RSSI 占位值、保留字段及校验状态；Status 后为 Average signal (dBFS) 和 Peak signal (dBFS)。奇偶行白/灰交替，可横向滚动并拖动表头调整列宽。只有通过 PHY CRC 和 LB CRC 的报文才填充协议解码列；无效或未知数值显示“—”。接收强度独立于应用协议是否通过。

接收强度统计每条报文经同步、补偿并抽样后的头部和负载复数 IQ（FFT 前，不含前导码）。平均强度为 `10 log10(mean(|IQ|²))`，峰值为 `10 log10(max(|IQ|²))`，以幅度 1 为参考，单位 dBFS。它不是经校准的射频功率 dBm，也不是发射端 RSSI 占位值。接收增益改变会影响读数。测量不完整时显示“—”，不使用邻近时段强度代替。

顶部 Device 菜单提供接收启停、手动指定 RTL-SDR 索引/序列号、刷新设备及退出；停止后才允许改设备。采样率、增益、ppm 直接在主界面配置。Logs 菜单提供显示设置、当前会话导出子菜单和历史日志另存。自动 JSONL 日志在 `logs/`，包含通过 PHY CRC 并合并后的报文、测量值及统计范围；GUI 仅显示最近 500 行，导出包含当前会话全部记录。

顶部 Language 菜单可在 English 和中文之间切换。左上配置区的“接收增益 / Receiver gain”滑块及同一行数值框可在接收过程中直接调整 0–50 dB 的 RTL-SDR 手动增益。调整会立即调用接收设备，表格里的强度读数会随增益变化。当前设备没有硬件或驱动支持时，调整失败会显示错误，不会伪造信号强度。

菜单 Visualization → Distance visualization（中文为“可视化 → 距离可视化”）切换内嵌距离区域的显隐。左侧为天线图标，设备标记直接落在右侧水平数轴上；横轴按每个设备最新平均信号强度估算相对位置。新报文到达时按设备 ID 原位更新标记、位置及标签高度，同一 ID 不会重复出现。超过设定超时（默认 15 秒）没有新报文后，标记和文字会变淡。该位置只用于相对显示：dBFS 未校准为 dBm，受增益、天线和传播环境影响，不能当作真实测距。

语言选择会保存，下次打开沿用。增益数值框支持小数，运行中按回车或失去焦点时应用；硬件可能选择最近的支持档位，界面读取设备实际增益更新显示。日志记录显示该行时的设备及增益（不是报文采样时的精确增益，刚调整时可能有缓冲报文）。语言切换不改变原始报文字节或机器可读日志字段。

使用字节流和 `frame_info` 标签获取 payload 长度及 `crc_valid`。没有把二进制 payload 当 Unicode/ASCII 消息解码，零字节和高位字节可以完整保留。PHY CRC 未通过时，不将内容当作可信 LB 数据。LB CRC16-CCITT 初值 0xFFFF，CRC 为小端存储，按 `../prog_test/main.py` 当前结构解析；RSSI 字段是发射端占位值，不是接收测量。

## 验证与目前的硬件阻塞

`Start-LoRaReceiver.ps1 --self-test` 做数字调制/解调回环，包括真实接收链所用的 1 MS/s → 500 kS/s 重采样，结果写入 `self-test-result.json`。4 个报文幅度依次为 1、0.5、0.25、0.125；同时验证解码、报文与强度对应及平均/峰值读数。`verify_gui.py` 使用合成数据检查分栏、频谱/瀑布、交替行、强度列、JSONL/CSV 导出和启停，预览保存为 `layout-preview.png`。这些测试不使用发射硬件，不是现场接收成功证据。

部署时 `rtl_test.exe -t` 报告 `No supported devices found.`，Windows PnP 枚举也未发现 VID_0BDA 的 RTL-SDR，当前无法验证真实发包。先将 RTL-SDR 插入本机并检查 USB 连接。只有设备已枚举但无法打开时，才检查 WinUSB 驱动；不要对其他 USB 设备更换驱动。典型 RTL2832U 在 Zadig 中选择其 Interface 0 并安装 WinUSB。设备连接后可运行：

```powershell
& 'D:\ProgramData\radioconda\Library\bin\rtl_test.exe' -t
```

收到 `PHY CRC OK / LB OK` 才表示报文通过两层校验。看到频谱、burst 或仅打开 GUI 均不能算解码成功。当前仍待现场验证。

## 文件

`receiver.py` 为专用 GUI；`RTL_SDR_LoRa_RX.grc` 为 GRC 工程；`generated/RTL_SDR_LoRa_RX.py` 为 GRC 编译结果。`prepare_grc.py` 可从已安装的 EPFL 示例重新生成默认流图，运行会覆盖 `.grc`，请先保存自行修改的版本。

解码模块来源：https://github.com/tapparelj/gr-lora_sdr 。接收流程基于已安装模块及其示例；GNU Radio 和相关模块的许可证保留在 radioconda 安装中。
